Deploy — the recommended way

The start script (macOS / Linux, and Git Bash on Windows)

bash scripts/start-jira-board.sh

Then open http://localhost:4321/dist/index.html ✓

It starts Docker if needed, builds the board on your machine (npm run build), packages that build into the image (DIST_SOURCE=prebuilt), frees port 4321, redeploys, waits until the board is healthy and opens it. Safe to run again and again — it never stacks containers or drifts ports. It needs Node.js 22+ for the build step.

First run: the board is empty and shows Add API keys first. Paste your Jira token there (or use the key button in the header), Save, then Refresh. The key is saved in setup/.env and works from the next fetch — no restart.

Without Node on the machine — plain Docker Compose

docker compose up -d --build

This builds the app inside the image instead. It works, but over a slow or flaky Docker network npm ci can silently skip the TypeScript compiler's platform binary and the build dies — see the FAQ. Compose starts project JIRA-Project with the JIRA-Board container, mounts ./setup (where the API keys dialog saves your keys), fetches once on boot, then on the schedule set in Settings.

Build and run by hand

Build the image, then run it

# build the board on this machine, then package it (what the start script does)
npm run build
docker compose build --build-arg DIST_SOURCE=prebuilt
docker compose up -d

# or plain docker, without compose (the Dockerfile lives in docker/)
docker build -f docker/Dockerfile --build-arg DIST_SOURCE=prebuilt -t jira-board:latest .
docker run -d --name JIRA-Board -p 127.0.0.1:4321:4321 \
  -v "$(pwd)/setup:/app/setup" \
  -v "$HOME/.ai:/home/node/.ai:ro" \
  -v "$(pwd)/jira-intern:/app/jira-intern" \
  jira-board:latest

Mount the folder setup/ (read-write — the key dialog writes setup/.env there), not the file itself: a save replaces the file, and a single-file mount would keep pointing at the old one. On a Linux host, setup/ and jira-intern/ must be writable by uid 1000. Windows PowerShell equivalents for the volume flags: -v "${PWD}\setup:/app/setup" and -v "${PWD}\jira-intern:/app/jira-intern".

Never add --pull to a build here: it re-downloads the base image every time, and Docker Hub can crawl from the Docker VM.

Manage the containers

Everyday commands

docker compose logs -f          # watch fetch + server logs
docker compose ps               # is it running?
docker compose restart          # restart without rebuilding
docker compose down             # stop and remove
bash scripts/start-jira-board.sh  # rebuild + redeploy after a code change
docker exec -it JIRA-Board sh   # shell inside the container
docker stats JIRA-Board         # resource usage
docker image prune -f           # clean old layers
Changed anything in src/? Redeploy with the start script — the app is baked into the image. Changing only data needs no rebuild; the container refetches on its own.

Desktop launcher

One-click launcher (macOS / Linux)

Starts Docker if needed, frees the port, rebuilds, redeploys, waits for health, and opens the board. Safe to run repeatedly — it never stacks containers or drifts ports.

./scripts/start-jira-board.sh

For a Desktop shortcut, copy setup/Start Jira Board.command.template to your Desktop, set REPO_DIR inside it, then chmod +x it and double-click.
