1 · Your Jira token — the key button

1

Create the token now, paste it in the board

In Jira: your avatar → Profile → Personal Access Tokens → Create token. Copy it straight away (Jira shows it once). Read scope is enough.

There is no file to edit. Once the board is running (page 05), a new install shows Add API keys first; otherwise click the key button beside Settings in the header (it has an amber dot while the Jira token is missing). Expand Jira, paste the token, Save, then Refresh. Bitbucket, Confluence and the Cloud AI keys (Claude, Cursor, Gemini) go in the same list, as do Jenkins and Checkmarx One — each row says why it's needed and where to get it. Every key and integration: page 11.

Where it is stored: setup/.env in your copy of the repo — git-ignored, kept out of the Docker image, never served by the board. A saved key is only ever shown masked (first and last few characters).

2 · Your personal config

2

Create your personal config

Your identity and company URLs live outside the repo, at ~/.ai/config.json, so they never enter git.

macOS / Linux:

mkdir -p ~/.ai
cp setup/config.example.json ~/.ai/config.json
chmod 600 ~/.ai/config.json

Windows (PowerShell):

New-Item -ItemType Directory -Force "$HOME\.ai" | Out-Null
Copy-Item "setup\config.example.json" "$HOME\.ai\config.json"

Edit it — your name exactly as Jira shows it (that's how "assigned to me" matches), your company URLs, and the footer branding. Every key is documented in docs/CONFIG.md. No tokens go in this file.

Config precedence: tracked defaults from config/jira-board.config.json, then a sparse $AI_CONFIG_FILE or ~/.ai/config.json override, then saved runtime Settings. Check with node jira-intern/local-runner/config.mjs path.

3 · The AI model lists (optional)

3

Local and cloud model lists

Every local LLM the intern can run — Ollama tags and direct GGUF downloads — lives in ai-intern/models.json. Settings and this guide both read that file. When a new model ships, add an object there (see the howto field at the top of the file) and restart AI-Intern. The cloud models (Cursor, Claude, Gemini), their efforts and what counts as costly are listed in ai-intern/cloud-models.json — see page 07.

Host Ollama (Settings checkbox on): install, pull, where files live. Checkbox off: download a GGUF, where to place it, how to register it.

Never commit your keys or your config. setup/.env is git-ignored and ~/.ai/config.json lives outside the repository on purpose. If you ever see an .env file or a config.json with your name in git status, stop and remove it from the commit.
