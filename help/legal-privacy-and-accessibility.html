Privacy Policy

The short version: everything runs on your computer. This application has no backend of its own, sends nothing to the project's authors, and contains no analytics, telemetry, crash reporting, advertising or tracking of any kind.

Who is responsible

You install and run My Jira Board yourself (Docker on your machine, or a local Node server). You are the operator of your own instance: the data it holds is yours, fetched with your own credentials, and it never leaves your machine except for the calls you configure (described in outbound connections).

What we — the project authors — receive

Nothing. The software makes no request to any server operated by this project. The only way the authors ever learn anything about your usage is if you choose to open a GitHub issue.

Other people's data on your board

Jira tickets naturally contain names of colleagues (assignees, reporters, reviewers, commenters). The board only mirrors data your Jira account can already see, under your employer's existing Jira terms and access controls. It adds no new collection — but the local copy is your responsibility: keep the machine it runs on appropriately protected, and treat exports of jira-intern/data.json like you would a Jira export.

Where processing happens

  • Fetching & rendering — entirely local (your machine / your Docker VM).
  • AI briefs & PR reports — optional. With a local model (Ollama), ticket text never leaves your machine. With a cloud model, the ticket text being summarised is sent to the provider you selected, under your own API key and that provider's privacy terms. Set Settings → AI usage to None and no AI processing happens at all.

Your rights, practically

Because everything is a plain file on your disk, every data-protection right is a file operation you can perform yourself — see deleting your data. Nothing needs to be requested from anyone.

Retention

Nothing expires on its own — files persist until you delete them, so your Completed archive can span years. That is a feature, and it is entirely under your control.

Deleting your data

  • All fetched data: delete jira-intern/data.json, data.js, cache/, reports/, logs/ (or docker compose down and remove the folder).
  • Credentials: remove each key in the API keys dialog (or delete setup/.env) and revoke the tokens in Jira/Bitbucket — revocation kills any copy instantly.
  • Browser state: clear site data for localhost:4321.
  • AI models & queues: docker volume rm jira-ai-models.

Cookie Policy

This application sets no cookies. None. There is no consent banner because there is nothing to consent to: no advertising cookies, no analytics cookies, no third-party cookies, no fingerprinting.

What it uses instead is your browser's localStorage — plain key-value storage that never leaves your browser, is never transmitted with requests, and is readable only by pages on the same origin (your own localhost):

KeyHoldsLifetime
jb-settingsTheme policy, feature toggles, AI level, parallelism, toast prefsUntil you clear it
jb-archivedTicket keys you manually moved to CompletedPruned automatically as tickets leave the dump
jb-completed-show-contextThe Completed view's "Mine only" toggleUntil you clear it
jb-guide-osWhich OS tab you picked in this help guideUntil you clear it

Clearing: browser settings → site data for localhost:4321 → remove. The board falls back to defaults on next load, losing nothing but preferences.

Third-party embeds & outbound connections

There are no third-party embeds. No CDN scripts, no web fonts fetched from font services, no iframes, no social widgets, no map or video embeds, no remote images. The board is a single self-contained HTML file; this guide and these policies are plain local pages. If your machine is offline, every page still renders.

Accessibility — alt text & colour contrast

The board aims for WCAG 2.1 AA. Accessibility work that is already in place:

Alt text & semantics

  • Informative graphics carry a text alternative — e.g. the setup guide's architecture diagram is an SVG with role="img" and a full aria-label description; purely decorative flourishes are marked aria-hidden.
  • Icon-only buttons (theme toggle, settings, close, expand) all carry aria-labels; toggles expose aria-pressed / aria-expanded, overlays use role="dialog" with focus management, and busy buttons set aria-busy.
  • The board renders no raster images at all — everything is text, SVG and CSS, so nothing can be missing alt text silently.

Colour & contrast

  • Light and dark themes both target AA contrast for text (4.5:1 body, 3:1 large/bold text); muted text is reserved for secondary information, never sole-source content.
  • Colour is never the only signal: every status pill carries its label text, priorities pair colour with a distinct glyph and tooltip, and PR states include text badges — so the board remains usable with colour-vision deficiency.
  • Both themes honour your OS preference automatically and can be fixed or scheduled manually.

Motion & input

  • Settings → Motion & animations disables all transitions (equivalent to prefers-reduced-motion); guide animations also respect the OS setting.
  • Keyboard: / focuses search, r refreshes, Esc closes the top layer only; shortcuts never fire while typing and can be switched off entirely.
Known gaps (honest list): the kanban columns are not yet fully traversable as a single keyboard grid, and some dense rail labels fall below AA at very small zoom levels. Found something else? Please report it — accessibility issues are treated as bugs, not feature requests.

Contact us

This is an open-source project — the repository is the front door, and issues are read by the maintainer:

  • Bug reports & feature requests: github.com/yo-sayantan/AI-JIRA-Board/issues

  • Privacy or accessibility feedback: same channel; reference the section of this page.

Running your own fork inside a company? Your internal operator (whoever deployed it) is the right first contact for data questions about that instance — they hold its files.
