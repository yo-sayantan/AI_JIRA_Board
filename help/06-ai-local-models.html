The AI Intern — what it is

Two containers, one command

docker compose up -d --build starts project JIRA-Project with JIRA-Board (fetch + UI), AI-Ollama, and AI-Intern (report enrichment, ticket briefs, model download). Both stay up with restart: unless-stopped. Refresh and Regenerate honour Settings — you do not need a host terminal for AI.

Settings → AI usage: None / Low / Moderate / Max, then Local or Cloud. Max is the product name for the stored value full (longest timeout). Local models are a dropdown. If the chosen tag is already on disk, that is enough. If it is not, the download icon beside the list queues a pull. The ? next to the list opens GGUF models — download a file, place it, register it. For Cloud AI the i next to the model list opens Cloud prices.

The catalog of every local LLM (tags + download links) is ai-intern/models.json — add a row there when a new model is released. Jump: Host Ollama · GGUF files.

Host Ollama — install, pull, deploy

When the Host Ollama checkbox is on

Settings → Local AI → tick Host Ollama. The intern then talks to Ollama.app on this Mac (Metal) at host.docker.internal:11434 instead of the Linux Docker VM (CPU). Use this for 14B+ if you can, and for every 32B / 70B tag.

1

Install Ollama and leave it running

Download Ollama.app, open it once, and keep it in the menu bar. First-run will listen on 127.0.0.1:11434.

2

Pull a model (or let Settings do it)

Easiest: pick the tag in Settings and click the download icon. Same thing from a terminal:

ollama pull qwen2.5-coder:7b

Weights land in ~/.ollama/models. Do not copy blobs into that tree by hand — Ollama owns it. Catalog: ollama.com/library. Default tag: qwen2.5-coder:7b.

3

Trigger it from the board

Host Ollama on, model selected (no download icon once it is installed), AI usage not None. Then Regenerate a PR report or Refresh — AI-Intern enqueues enrichment against that tag. Idle status in Settings should read Idle · local · <tag>.

Download a GGUF — place, register, trigger

When Host Ollama is off

The intern uses the AI-Ollama container. You can still skip ollama pull and drop in a file you already have — but a raw .gguf is invisible until you ollama create it with the same tag the Settings dropdown uses (id in ai-intern/models.json).

1

Download the file

Use a direct download from the table (Hugging Face resolve/main URL — the browser saves the .gguf). Q4_K_M is the size/quality sweet spot. 32B+ files are large and may be split on the repo page; if a direct link 404s, open the repo and pick the matching quant.

ModelFileDirect downloadRepo
Loading the model list… (this needs JavaScript; the list itself is ai-intern/models.json)

Other sources: Hugging Face GGUF, bartowski quants, Ollama library (pull instead of a file).

2

Where to place it

Save the file in jira-intern/models/ (git-ignored). That directory is the AI-Ollama container's model store (/root/.ollama), and a model there is what lets the container start — with Settings → Features → AI-Ollama container on. Ollama still will not list it until you register it.

mkdir -p jira-intern/models
# move the downloaded .gguf in here, e.g.
# mv ~/Downloads/qwen2.5-coder-7b-instruct-q4_k_m.gguf jira-intern/models/
3

Register the tag (how to trigger)

In-container (Host Ollama off) — the file is already inside the container at /root/.ollama/; create it with the Settings tag:

docker exec AI-Ollama sh -c 'printf "FROM /root/.ollama/qwen2.5-coder-7b-instruct-q4_k_m.gguf\n" > /root/.ollama/Modelfile && ollama create qwen2.5-coder:7b -f /root/.ollama/Modelfile'

The created model lands in jira-intern/models/ on this machine, so it survives container rebuilds and redeploys.

Host Ollama — same file, then:

cat > /tmp/Modelfile <<'EOF'
FROM /absolute/path/to/qwen2.5-coder-7b-instruct-q4_k_m.gguf
EOF
ollama create qwen2.5-coder:7b -f /tmp/Modelfile

That writes into ~/.ollama/models. Tick Host Ollama so the intern uses it.

Then from the board: Settings → pick the matching tag (download icon disappears once the tag exists) → AI usage not None → Regenerate / Refresh. The intern enqueues the job; you do not need a host console.

Add a newly released model

One entry in models.json

Edit ai-intern/models.json. Copy an existing object, set id / pull to the Ollama tag you will ollama create or ollama pull, fill ollama (library URL) and gguf (direct .gguf URL), then restart the intern:

docker compose up -d --build jira-ai

The Settings dropdown and both tables on this page pick up the new row from that file (opened from disk, this page shows the copy made by the last npm run build). No UI change is required.

Honest gap. Local models (including Gemma / GPT-OSS / nano) read the intern volume and live Jira/Bitbucket REST (same tokens as Cursor MCP). A live Dynatrace search of the ticket's text is only tried for observability / incident tickets that have no Dynatrace link; the links a ticket does contain are read by the board's fetch (see the API keys page) and feed the report's Issue insight. CI and Checkmarx are the exceptions once set up: the "CI green" gate is read from the ticket's latest Jenkins builds, and on a vulnerability-fix ticket the "Security scan (Checkmarx) clean" gate from which of the vulnerabilities it names Checkmarx One shows as fixed on its branch (both fetched with the board, no AI needed).
